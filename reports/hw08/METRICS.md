## Comparison with the HW2 in-process graph

**Benefits gained by moving to Kafka**

1. Decoupled failure: when the Writer was killed, the Planner and Reviewer kept running and the task waited in `s0036_tasks` until the Writer restarted and finished it. In HW2 one exception in a node stopped the whole graph run.
2. Independent scaling: a second Writer joined the same consumer group and Kafka split the two partitions of `s0036_tasks` between them, with no change to the Planner or Reviewer.

**New responsibilities I now handle myself**

1. Duplicate delivery: Kafka is at-least-once, so a replayed or redelivered message is processed again unless each agent is idempotent (persisted set of completed correlation_ids).
2. Ordering and offsets: order holds only within one partition, so related messages need a key; and offsets must be committed only after the output is in Kafka, with bounded retries plus a dead-letter topic so one bad message cannot block a partition. In HW2 a function call simply returned in order, exactly once.
